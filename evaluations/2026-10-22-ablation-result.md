# React composition skill 축약 평가

## 선택한 본문

스킬 본문에서 평가 절차와 일반적인 검증 설명을 빼고, 기사에서 가져온 네 단계의 경계 판단을 중심으로 줄였다. 현재 [SKILL.md](../skills/react-composition/SKILL.md)는 frontmatter를 포함해 133단어·942바이트로, 축약 전 587단어·5,096바이트보다 단어 수 77%, 바이트 수 82% 줄었다. 사례 파일·평가 기준은 각 후보에서 동일하게 사용했다.

| 후보 | 파일 단어 수 (frontmatter 포함) | Luna 결과물 점수 평균 | 반복 | 관찰 |
| --- | ---: | ---: | ---: | --- |
| 원문 본문 | 587 | 0.97 | 1 | 기준선. 기존 진입점·보드 상태 초기화 통과, 비동기 오류 항목 실패 |
| v1 compact | 253 | 0.92 | 1 | 기존 진입점의 기본 동작·설명 불일치 |
| v2 core | 167 | 0.93 | 1 | source hook 경계, 화면 배치 플래그 실패 |
| v3 minimal | 118 | 0.96 | 1 | source hook 배치 기준 실패 |
| v4 guarded core | 197 | 0.91 | 2 | 레이아웃 순서·배치 플래그·이벤트 오류 기준에서 실패가 반복됨 |
| **v5 hook boundary (선택)** | **133** | **0.95** | **2** | 기존 진입점·공급자 경계·fixture·보드 상태 초기화 통과. 비동기 오류 2회, 배치 순서 1회 실패 |

v5는 v3의 짧은 본문에 “조회 훅은 각 공급자 안에서 호출하고 fixture는 live 조회를 부르지 않는다”는 경계만 더했다. 기존 본문과 비교해 점수 차이는 0.02였고, 미적용 기준 0.89보다 0.06 높았다. 5개 사례와 두 번 반복한 작은 표본이므로 동등한 성능을 증명하지는 않는다. 특히 점수 차이에는 모델 샘플 변동과 같은 Luna 모델을 사용한 독립 리뷰의 판단이 포함된다.

실제 코드에서도 v5가 source 경계를 더 명시했는지 확인했다. 비동기 사례의 빈 `catch`와 한 번 나온 배치 순서 실패는 축약 스킬만으로 해결되지 않았다. 비동기 이벤트의 오류 전달을 스킬 범위에 다시 포함할지는 다음 별도 판단으로 남긴다.

## 실험 절차와 범위

- 모든 후보는 `gpt-6-luna`, 추론 강도 `low`로 생성하고 같은 모델로 독립 리뷰했다. 축약 후보는 `with` 조건만 실행해 각 후보마다 5개 사례 × 반복 수 × 생성·리뷰로 평가했다.
- 결과물 기준은 기존 Luna 사례와 동일하다. 후보 프롬프트에는 해당 후보 본문만 넣었고, judge에는 본문과 적용 여부를 숨겼다.
- 평가 중 judge가 설명문 근거를 정확히 인용하지 못하거나 CLI 호출이 일시 실패한 응답은 점수에 넣지 않았다. 유효한 동일 프롬프트를 재사용하거나 리뷰만 다시 호출해 각 최종 보고서를 완성했다.
- 이번 점수는 생성 코드의 정적 리뷰다. 컴파일·런타임 동작은 평가하지 않았다. 평가 절차는 `evaluations/`에 두고 스킬 본문에는 포함하지 않는다.
