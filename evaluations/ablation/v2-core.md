# React 합성 설계

props로 시작한다. 실제 사용 문제를 해결하는 가장 작은 경계를 선택하고, 구조 통일만을 위한 추상화는 피한다.

| 상황 | 경계 |
| --- | --- |
| 작고 안정적인 API | props와 로컬 상태 |
| 호출부별 배치 변화 | 호출부에서 조립하는 하위 컴포넌트 |
| 같은 UI, 다른 데이터 출처 | 출처 독립 UI와 공통 계약을 구현하는 provider |
| 형제 간 공유 상태·액션 또는 먼 계층까지 전달 | 공통 상위의 기능 provider; 말단 상태는 로컬 |

기존 호출부와 동작을 유지한다. 상태·액션을 옮기면 인자, 반환·실패, pending, 캐시와 초기화를 보존한다. 필요한 값만 계약에 넣고, 이름·React API·디자인 시스템은 프로젝트 관례를 따른다. 필요한 단계의 [레퍼런스](references/examples.md)만 참고한다.
