# React 합성 설계

props로 시작하고, 확인된 사용 문제를 가장 작은 추상화로 해결한다. 구조 통일만을 위해 추상화하지 않는다.

| 문제 | 검토할 경계 |
| --- | --- |
| API가 작고 안정적 | props와 로컬 상태 유지 |
| 호출부마다 배치가 달라 기존 API로 표현 불가 | 호출부가 조립하는 하위 컴포넌트. 컴포넌트 상태는 props로, 내부 협력만 비공개 context로 |
| 같은 UI에 교체 가능한 데이터 출처 필요 | 출처를 모르는 UI와 작은 계약을 구현하는 provider |
| 형제끼리 상태·액션을 공유하거나 무관한 계층에 전달 | 공통 상위의 기능 provider. 말단 상호작용 상태는 로컬 유지 |

데이터 출처는 provider 뒤에 둔다. 계약은 필요한 상태·메타·액션만 담는다.

## 적용 시 보존할 것

- 호출부, 설치된 React 버전과 프로젝트 관례를 살핀다. 필요한 최소 변경을 하고 공개 API와 기존 동작을 유지한다.
- 상태·액션을 옮길 때 인자, 반환·실패, 처리 중 표시, 캐시 갱신과 초기화를 보존한다. 필수 provider 누락은 명확히 오류 낸다.
- 프로젝트가 지원하는 context API와 디자인 시스템을 쓴다. 의미 있는 HTML, 키보드·레이블·ref·이벤트 동작을 보존하고 상호작용 요소를 중첩하지 않는다.
- 지연 조회는 실제 마운트나 query 실행을 제어한다. Suspense만으로 이미 시작한 effect 조회를 늦출 수 없다.

필요한 단계의 [레퍼런스](references/examples.md)만 참고한다.
