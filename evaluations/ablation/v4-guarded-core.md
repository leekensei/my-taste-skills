# React 합성 설계

props부터 시작해 실제 사용 문제를 해결하는 가장 작은 경계를 고른다. 구조를 맞추려는 추상화는 피한다.

| 문제 | 경계 |
| --- | --- |
| 작고 안정적인 UI API | props와 로컬 상태 |
| 화면별 배치 변화 | 호출부가 조립하는 하위 컴포넌트. `dense` 같은 UI 자체 속성은 prop으로 |
| 같은 UI에 live·fixture 등 출처 교체 필요 | 출처 독립 소비자와 작은 계약. 조회 훅은 해당 출처 provider에서만 호출하고 fixture는 live 조회를 호출하지 않는다. 기존 진입점은 기본 provider를 감싸 호출 호환성을 유지한다. |
| 형제 간 상태·액션 공유 또는 무관한 계층으로 전달 | 가장 가까운 공통 상위의 기능 provider. 말단 상호작용 상태는 로컬 유지 |

기존 API와 동작을 보존한다. 상태·액션 이동 시 인자, 반환·실패, pending, 캐시 갱신과 초기화를 유지한다. 프로젝트가 지원하는 React API와 관례를 따른다. 필요한 단계의 [레퍼런스](references/examples.md)만 읽는다.
