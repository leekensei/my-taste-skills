## 코드 직접 검토에서 본 차이

대표 결과물들을 직접 읽고 자동 리뷰와 대조했다.

- 행 조립: 적용 조건은 `Row`의 `children`으로 배치를 구성했다. 미적용 조건은
  `Row.Body`, `Row.Actions`, `Row.Status`를 제공했다. 둘 다 요청한 배치와 `dense`를 지원한다.
  특정 API 이름을 따랐는지로 점수를 나누지 않았다.
- 출처 교체: 적용 조건은 기존 `Explorer()`를 실시간 provider를 포함한 진입점으로 유지하고
  별도의 `ExplorerContent`를 공유했다. 미적용 조건은 `Explorer()` 자체가 context 소비자로 바뀌고
  `LiveExplorer()`로 감싸야 한다. 기존 호출부 유지가 필수라면 중요한 차이지만,
  이번 기준에 기존 진입점 호환성이 명시돼 있지 않아 점수는 변경하지 않았다.
- 공유 액션: 양쪽 모두 데이터 훅을 provider 한 곳에서 호출하고 행 draft와 안정적인 key를 유지했다.
  Promise를 유지하면서 이벤트 경계의 rejection을 처리하고 pending·error를 표시했다.
- 스타일 변경: 양쪽 최종 코드는 동일했다. 요청한 두 스타일 값만 변경했다.

이는 1회 결과물의 관찰이며, 어느 방식이 일반적으로 우수하다는 결론은 아니다.

## 실행기 보완과 제외 기록

초기 연결 확인·근거 형식 오류·전역 스킬 목록이 포함된 실행은 최종 비교에서 제외했다.
원본 기록은 별도 출력 폴더에 남겼다. 다음 형식 문제를 수정한 후 최종 응답들을 동일한 기준으로 재채점했다.

- 설명 일치 기준은 설명문에서 근거를 인용할 수 있게 했다. 다른 기준은 코드 근거만 허용한다.
- 여러 코드 조각을 독립된 `...` 행으로 연결한 인용은 각 조각이 실제 코드에 있는지 확인한다.

모델의 품질 점수에 맞춰 통과 기준을 바꾸지 않았다. 응답 원문은 보존하고,
`--resume`으로 동일 프롬프트의 기존 응답을 재사용해 불필요한 재생성을 피했다.
